# WFP datagram-proxy 한국어 설명

이 샘플은 프로그램이 `원래 UDP 포트`로 보낸 데이터그램을 커널에서
`프록시 UDP 포트`로 바꿔 보내는 예제입니다.

역할은 다음처럼 분리됩니다.

- 컨트롤러: 두 UDP 수신 포트를 만들고 동적 WFP 규칙을 설치합니다.
- flow callout: 조건에 맞는 UDP 흐름에 프록시 포트를 typed context로
  연결합니다.
- datagram callout: UDP 패킷을 복제하고 목적지 포트를 변경한 뒤 다시
  주입합니다.
- `ntl::wfp`: flow context 제거, 복제 패킷 소유권, 비동기 주입 완료와
  드라이버 언로드 대기를 담당합니다.

실행 시 확인하는 순서:

1. 원래 포트와 프록시 포트를 각각 엽니다.
2. `ALE_FLOW_ESTABLISHED_V4`와 `DATAGRAM_DATA_V4` 규칙을 한 트랜잭션으로
   설치합니다.
3. 원래 포트로 UDP 데이터를 보냅니다.
4. 프록시 포트만 데이터를 받는지 확인합니다.
5. 동적 WFP 세션을 닫습니다.
6. 다시 원래 포트로 보내 원래 포트가 받는지 확인합니다.

드라이버는 재주입한 패킷을 `FwpsQueryPacketInjectionState`로 식별해
다시 프록시하지 않습니다. 복제·수정·재주입 중 하나라도 실패하면
원본을 통과시키지 않는 fail-closed 규칙을 사용합니다.

드라이버를 적재할 때 UDP 헤더를 두 MDL로 나눈 자체 시험도 실행합니다.
목적지 포트가 MDL 경계를 가로질러도 `scatter_view` 편집이 성공하는지,
깊은 복사의 최대 길이 제한이 허용·거부 경계에서 정확히 동작하는지
실제 NBL로 확인한 후 callout을 만듭니다.

지원 범위는 `outbound IPv4 UDP 목적지 변경`과 주입 소유권입니다. 응답
패킷의 주소·포트를 복원하는 투명 양방향 프록시, IPv6과 IPsec에는 추가
정책과 adapter가 필요합니다.
