# I/O 버퍼 매핑 및 스와핑 구현 체크리스트

이 파일은 NTL 구현의 완료 상태를 지속적으로 기록합니다. 각 항목은 코드와 그에
상응하는 빌드·테스트 증거가 확보된 뒤에만 완료로 표시합니다.

## 완료

- [x] 프로세스 범위 `MmMapLockedPagesSpecifyCache(UserMode)` 브리지는 WDK의 실제
  `KAPC_STATE`, 프로세스 종료 동기화, NX, 선택적 읽기 전용 매핑을 사용합니다.
- [x] 연결 레지스트리는 매핑 ID와 세대를 할당하며, 동기 연결 해제 종료 처리가
  시작된 뒤에는 새 매핑을 거부합니다.
- [x] 명시적 매핑 닫기는 복사된 뷰를 무효화하고 대상 프로세스에서 매핑을 해제한
  뒤 등록을 취소하고, 소유한 MDL과 스테이징 저장소를 해제합니다.
- [x] 격리된 SystemBuffer 스테이징은 매핑을 닫을 때까지 유지되며, 사용자 매핑이
  열려 있는 동안에는 출력을 되쓸 수 없습니다.
- [x] METHOD_NEITHER 페이지 검사는 원래 IRP 요청자 프로세스에서 실행합니다.
- [x] 완료된 READ/IOCTL 출력 길이는 `IoStatus.Information`으로 제한할 수 있습니다.
- [x] METHOD_IN_DIRECT의 직접 MDL은 입력으로 취급하고, 별도의 시스템 제어 헤더는
  `control_input()`으로 노출합니다.
- [x] 미니필터 매핑은 단계가 형식화된 `as_pre`/`as_post` 진입점과 read/write,
  파일 정보, 디렉터리, EA, 볼륨, 보안, FSCTL, IOCTL 어댑터를 제공합니다.
- [x] 원시 콜백 데이터/단계 구현은 내부 전용입니다. 공개 매핑 API에는 형식화된
  pre/post 작업이, 공개 교체 API에는 형식화된 pre 작업이 필요합니다. 컴파일
  어설션은 지원되는 모든 작업 형식을 다루고 원시 호출과 post 교체를 거부합니다.
- [x] 교체 버퍼의 매핑은 입력 적용이나 출력 되쓰기 전에 닫아야 합니다. 파괴와
  `complete()`는 남은 매핑을 닫고, 활성 매핑 해제 실패는 안전하지 않게 완료하지
  않고 오류를 보고하여 보류 상태에 유지합니다.
- [x] Fast I/O 교체는 명시적으로 거부하므로 호출자가 Fast I/O를 허용하지 않고 IRP
  경로에서 재시도할 수 있습니다.
- [x] FSCTL/IOCTL 교체는 buffered 공유 backing, direct 제어 입력,
  METHOD_IN_DIRECT 페이로드 입력, METHOD_OUT_DIRECT 출력, NEITHER 입력/출력을
  대칭적인 적용/복원 어댑터로 처리합니다.
- [x] 형식화된 post-operation 되쓰기는 실패한 작업을 거부하고 길이를
  `IoStatus.Information`으로 제한하며, 사용자 매핑이 열려 있으면 거부합니다.
- [x] MDL 시스템 주소가 없을 때 원시 미니필터 입력 복사와 출력 되쓰기는 Filter
  Manager 요청자 프로세스에 연결한 상태에서 수행합니다.
- [x] 사용자 모드 `mapped_client_buffer`는 데이터를 노출하기 전에 세대, 접근 권한,
  예약 필드, 포인터 너비, 범위 오버플로를 검사합니다. x64/x86 단위 테스트가 정상,
  오래된 세대, 읽기 전용, 잘못된 접근 권한, 오버플로 사례를 다룹니다.
- [x] Filter Manager에는 별도의 교체 MDL을 제공하며 이 부분 MDL만 소유하게 합니다.
  NTL은 페이지가 격리된 원본 MDL을 유지해 이중 해제를 막고 원래 잠긴 페이지
  설명을 보존합니다.
- [x] 비캐시 read/write 교체 용량은 대상 볼륨의 섹터 크기로 반올림하지만, 공개
  논리 뷰와 되쓰기 범위는 원래 요청 길이로 제한합니다.
- [x] 매핑/교체 어댑터는 read/write, 정보, 디렉터리, EA, 볼륨, 보안, FSCTL,
  IOCTL뿐 아니라 create EA와 query/set quota도 지원합니다.
- [x] `STATUS_BUFFER_OVERFLOW` 같은 경고 완료는 유효한 부분 출력을 버리지 않고
  `IoStatus.Information` 바이트를 보존해 노출합니다.
- [x] 자동 어댑터는 커널 요청자와 비페이징 풀 MDL에 격리된 스테이징을 사용하므로,
  페이지 단위 사용자 매핑이 인접 커널 데이터를 노출하지 않습니다.
- [x] 연결, 스테이징, 교체 할당량이 유지 중인 VAD와 격리된 물리 저장소를 제한하며,
  페이징 I/O 왕복은 기본적으로 거부합니다.
- [x] 연결의 매핑 바이트 할당량은 논리 바이트 수가 아니라 MDL 바이트 오프셋을
  포함해 페이지 단위로 반올림한 전체 VAD 범위를 계산합니다.
- [x] 스테이징 및 교체 할당량도 각 독립 논리 버퍼에 대해 페이지 단위로 반올림한
  물리 할당량을 계산합니다.
- [x] 연결 및 보류 요청 세대는 프로세스 전체에서 단조 증가하는 시드를 사용하므로,
  재연결이나 재구성 직후 오래된 wire ID와 겹치지 않습니다.
- [x] `FltCbdq` 목록 보호는 DISPATCH_LEVEL에서 안전하고 강제 정리는
  PASSIVE_LEVEL로 지연합니다. 삽입/취소 경쟁에서도 보류 소유권을 보존하며, post
  레지스트리 종료는 테이블에서 이미 제거된 응답까지 기다립니다.
- [x] Filter Manager 지연 I/O 도우미는 매핑, IPC, 레지스트리 작업 전에 pre/post
  콜백을 PASSIVE_LEVEL 작업자로 넘깁니다.
- [x] 명시적 닫기와 연결 해제가 동시에 발생하면 매핑 해제, 스테이징 되쓰기,
  소유 리소스 정리, 레지스트리 제거가 모두 끝날 때까지 기다립니다.
- [x] 자동 IRP/미니필터 매핑은 논리 범위가 완전한 페이지를 정확히 덮을 때만 원래
  사용자 MDL을 제로 카피로 노출합니다. 신뢰할 수 있는 서비스 정책에서 명시적으로
  선택하지 않는 한 부분 페이지에는 격리된 스테이징을 사용합니다.
- [x] 일반 IRP 매핑은 버퍼가 있는 사용자/커널 FSCTL 부기능을 지원하되,
  마운트/검증/파일 시스템 로드 요청을 일반 FSCTL 레이아웃으로 해석하지 않습니다.
- [x] 디렉터리 어댑터는 확장 변경 알림을 지원하며, 미니필터 FSCTL 어댑터는 버퍼
  레이아웃을 사용하지 않는 minor function을 거부합니다.
- [x] 제공되거나 새로 얻은 모든 MDL은 시스템 주소로 매핑하거나 복사하기 전에
  상주 페이지 플래그와 바이트 수를 검사합니다.
- [x] 리소스 고갈 경로에서는 프로세스 참조, 페이지 MDL, 시스템 매핑,
  `shared_ptr` 제어 블록 실패 각각의 소유자를 하나로 유지합니다.
- [x] 프로세스 종료 동기화 실패만으로 MDL backing을 해제하지 않습니다. 현재
  프로세스에서 매핑을 해제하거나 원격 주소 공간의 해체를 기다립니다.
- [x] 교체 출력 되쓰기는 콜백 데이터 ID를 확인하며, `complete()`는 매핑 닫기
  실패를 무시하지 않고 보고합니다.
- [x] 교체 완료 컨텍스트, 페이지 소유자와 제어 블록, 매핑 상태의 weak control,
  CBDQ에서 볼 수 있는 pre 상태는 명시적으로 비페이징입니다. 매핑 레코드를 제거한
  뒤 정리만 수행하는 post 완료는 DISPATCH_LEVEL까지 안전합니다.
- [x] 연결 종료 처리는 진행 가능한 모든 매핑을 계속 닫으면서 최초 정리 실패를
  보존합니다. 실제 활성 매핑 해제 실패만 명시적 재시도를 위해 해당 실행을
  중단합니다.
- [x] 연결 종료 처리는 사용자 VAD를 만들었지만 아직 레지스트리에 삽입하지 않은
  매핑 시도도 기다립니다. 따라서 동시에 거부된 매핑이 해제되기 전에 연결 해제가
  반환되지 않습니다.
- [x] Filter Manager 통신 연결은 접속 프로세스와 해당 매핑 레지스트리를 자동으로
  유지합니다. 포트별 VAD 제한을 구성할 수 있고, 연결 해제 시 관찰자 콜백보다 먼저
  레지스트리를 닫습니다. 미니필터 호출자는 현재 프로세스를 다시 캡처하거나 나중에
  PID를 조회하지 않고 `mapping_process()`를 사용합니다.
- [x] buffered 스테이징은 용량, 초기화된 입력 바이트, 쓰기 가능한 출력 되쓰기
  바이트를 따로 추적합니다. 더 큰 출력 용량은 초기화되지 않은 SystemBuffer 꼬리에서
  복사하지 않고 0으로 채웁니다.
- [x] WDM 런타임 픽스처는 이제 실제 대상 프로세스 VAD에서 사용자 읽기/쓰기,
  커널 관찰, 명시적 닫기, 핸들 정리, 갑작스러운 프로세스 종료, 세대 무효화,
  멱등적인 반복 종료 처리 및 네 가지 IOCTL 방식을 모두 실행합니다.
- [x] WDM 커널 픽스처는 자동 READ/WRITE 입력·출력의 형태도 검증합니다.
  접근 권한과 스테이징 되쓰기, 부분 경고 완료 길이 제한과 변경되지 않은 출력
  꼬리, 치명적 오류 시 출력 억제, 버퍼드 FSCTL의 공유 backing 및 버퍼를 사용하지
  않는 FSCTL 부기능 거부도 검증합니다.
- [x] 전용 미니필터 런타임 드라이버/앱 쌍은 pre-write 교체를 실행하고 양방향 교체
  버퍼를 연결된 사용자 서비스에 매핑합니다. 서비스에서 쓰기 전 암호화와 읽기 후
  복호화를 수행하고 적용/되쓰기 전에 VAD를 닫아 무효화합니다. 또한 Fast I/O 재시도,
  PASSIVE_LEVEL 지연, 서비스 연결 해제 후 I/O 거부, 언로드/재로드 소유권, 필터
  아래 암호문을 검증하며, 서비스 시간 초과·포트 연결 해제·인스턴스 해체 동안
  보류 중인 pre-WRITE와 post-READ를 능동적으로 취소합니다.
- [x] 관리자 권한 실행기는 Verifier 없이 조용히 실행하는 대신, 각 런타임 드라이버가
  이미 활성 Driver Verifier 대상인지 요구할 수 있습니다.

## 완료 게이트

- [x] 응답, 시간 초과, 취소, 연결 해제, 프로세스 종료, 언로드를 처리하는 보류
  pre/post 작업 및 요청 레지스트리 상태 머신을 추가했습니다.
- [x] 형식화된 단계, `control_input`, 모든 작업 어댑터, 지연 연속 실행,
  명시적인 적용/닫기 순서에 대한 컴파일 검증을 추가했습니다.
- [x] 매핑, 출력 되쓰기, 연결 해제/정리, 프로세스 종료, 교체, Fast I/O, 지연,
  Verifier 필수 실행을 검증하는 런타임 테스트를 구현했습니다.
- [x] 테스트 서명이 활성화된 커널 테스트 장비에서 WDM 및 미니필터 런타임 테스트를
  Driver Verifier와 함께 실행했습니다.
- [x] 공개 문서와 예시를 최종 API로 조정합니다.

## 새로 발견하고 자율적으로 해결

- 직접 IOCTL에는 제어 헤더와 직접 페이로드가 함께 들어갈 수 있으므로, 단일
  `input()`만으로는 METHOD_IN_DIRECT의 의미를 보존할 수 없습니다.
- 명시적인 닫기 연산 없이 약한 매핑 뷰를 반환하자 연결이 끊길 때까지 매핑이
  유지됐습니다. 이제 복사된 뷰가 하나의 명시적 닫기 상태를 공유합니다.
- 빌더 인수가 가진 스테이징 소유권이 실제 매핑 전에 끝났습니다. 이제 등록된 매핑
  상태 자체가 해당 저장소의 소유권을 유지합니다.
- 사용자 모드가 교체 입력을 변경하는 동안 입력을 설치하거나, 교체 출력을 변경하는
  동안 출력을 되쓸 수 있었습니다. 이제 두 작업 모두 매핑이 닫힐 때까지 거부합니다.
- 미니필터 post 콜백은 원래 요청 프로세스 컨텍스트에서 실행된다는 보장이 없습니다.
  원시 포인터 복사는 이제 `FltGetRequestorProcess`가 반환한 프로세스에 연결합니다.
- METHOD_BUFFERED 제어 요청은 입력과 출력에 같은 물리 포인터를 사용합니다. 이제
  하나의 격리된 backing 할당을 사용하고, 입력 변환만 요청해도 출력을 반드시
  추적합니다.
- 복사된 `swapped_buffer_view`가 추적되지 않은 두 번째 사용자 매핑을 열어
  `apply()`/되쓰기 배타 규칙을 우회할 수 있었습니다. 이제 뷰는 이동 전용입니다.
- Filter Manager는 post-operation 뒤 교체 MDL을 해제합니다. 이제 NTL은 자신이
  소유한 backing MDL을 넘기거나 PFN 관계를 다시 만드는 대신, 잠긴 backing MDL에서
  파생한 별도의 부분 전송 MDL을 만듭니다.
- 파일 시스템은 캐시되지 않은 버퍼를 섹터 크기로 반올림해 접근할 수 있고 경고
  상태에도 유효한 바이트가 포함될 수 있습니다. 용량 및 완료 상태 처리는 이제
  이러한 계약을 따릅니다.
- `FAST_MUTEX`는 `DISPATCH_LEVEL` 취소 큐 잠금으로 유효하지 않습니다. CBDQ는 스핀
  잠금을 사용하고, 비용이 큰 정리는 모두 PASSIVE_LEVEL 작업자에서 수행합니다.
- 객체별 세대 값이 1부터 다시 시작해 새 연결이나 레지스트리에서 이전 값과 겹칠 수
  있었습니다. 이제 세대 값은 전역으로 발급합니다.
- 레지스트리 항목을 스테이징 되쓰기보다 먼저 제거해 연결 해제 종료 처리가 너무
  일찍 반환할 수 있었습니다. 이제 항목 제거와 닫기 이벤트 신호를 마지막에 합니다.
- 설명자의 길이는 MDL로 만든 페이지 단위 VAD의 범위를 제한하지 않습니다. 자동

  접근은 MDL의 별도 비페이징 시스템 매핑을 사용합니다. 기준 뷰, 매핑 MDL, 섹션
  backing은 crtsys에 연결된 마지막 드라이버 참조가 해제할 때까지 유지합니다.
- 다음으로 확인된 로드는 WDM에서 잠금 제거 수명 위반을 노출했습니다.
  회귀 테스트. IOCTL 파이프라인은 다음과 같이 호출됩니다.
  스택 지역 remove lock에 `IoReleaseRemoveLockAndWait`를 호출한 뒤,
  `ntl_remove_lock_test`가 확장된 커널 스택이 같은 주소를 재사용한 상태에서 다른
  잠금을 초기화했습니다. Driver Verifier는 현재 스레드의 스택 범위 안에 있는
  remove-lock 주소와 함께 `0xC4/0xD7`을 보고했습니다. 이제 두 단발성 테스트는
  서로 다른 드라이버 이미지 수명 잠금을 사용하며, 공개 래퍼 문서에는 remove-lock
  저장소가 안정적인 비페이징 메모리여야 하고 같은 주소에서 재구성하거나 다시
  초기화하면 안 된다고 명시합니다.
- Windows 11 빌드 22000에서는 휘발성 Driver Verifier 상태로 새 대상과 표준형
  플래그를 활성화하자 대상 드라이버가 로드되기 전에
  `nt!VF_FIND_DEVICE_INFORMATION_AND_REMOVE`에서 운영 체제 `0xA` 버그 체크가
  발생했습니다. 따라서 이 검증 절차에서는 휘발성 활성화를 제외하고, 최종 실행은
  부팅 시 설정한 표준 옵션만 사용합니다.
- `ntl::status`는 성공 값이 0인 기본 `NTSTATUS`로 변환되므로, 부울처럼 검사하면
  성공과 실패의 의미가 뒤집힙니다. 이제 매핑, 교체, 보류 I/O, 런타임 테스트,
  연결 닫기 경로는 명시적인 `is_ok()`/`is_err()` 검사를 사용합니다. 수정 후 WDM
  테스트는 METHOD_BUFFERED, IN_DIRECT, OUT_DIRECT, NEITHER의 모든 매핑과 되쓰기
  사례를 통과했습니다.
- 첫 번째 미니필터 WRITE 교체 검증에서는 `IoBuildPartialMdl`에서 `0x12E`
  (`INVALID_MDL_RANGE`)가 발생했습니다. `page_buffer`의
  `MmAllocatePagesForMdlEx` MDL은 `MappedSystemVa`가 null이 아니어도 `StartVa`가
  null일 수 있습니다. 부분 MDL 범위는 임시 커널 매핑이 아니라
  `MmGetMdlVirtualAddress(SourceMdl)`를 기준으로 나타내야 합니다. 이제 교체 MDL은
  원본 MDL의 가상 범위로 만들고, 페이지 격리 시스템 매핑은 실제 교체 버퍼
  포인터로 계속 사용합니다.
- 부분 MDL을 수정한 뒤에는 사용자 변환과 `pending_pre_operation_queue::resume`이
  모두 성공을 보고했는데도 첫 WRITE가 무기한 보류됐습니다. 실행 중 콜백 데이터를
  확인하자 IRP는 CBDQ에서 제거됐고 `finish_phase == 2`였지만 완료 컨텍스트가 없고
  하위 스택도 호출되지 않았습니다. `claim_finish()`는 `ntl::status`를 반환하는데
  `if (!claimed)`로 검사하면서 `STATUS_SUCCESS == 0`을 true로 해석해 `apply()`,
  `release_completion_context()`, `FltCompletePendedPreOperation` 전에 반환한 것이
  원인이었습니다. 이제 재개와 취소는 명시적으로 `is_ok()`를 사용하고, 인스턴스별
  post 레지스트리 초기화에 있던 같은 상태 반전도 수정했습니다. 또한
  `ntl::status`의 문맥적 부울 변환을 삭제하고 컴파일 시간 회귀 어설션으로 이후
  `if (status)`/`if (!status)` 사용을 막습니다.
- 첫 번째로 완료된 미니필터 런타임 실행이 언로드에 도달했을 때, Filter Verifier는
  일반 작업 항목 두 개를 해제한 호출 필터를 식별하지 못해 오래된
  `FLT_GENERIC_WORKITEM` 추적 레코드 두 개를 유지했다고 경고했습니다. 기록된 객체
  주소는 이미 해제되어 관련 없는 풀 태그로 재사용된 상태였습니다. 디스어셈블리
  결과 모든 `generic_work::invoke`가 `FltFreeGenericWorkItem`으로 tail `jmp`해
  Verifier가 귀속에 사용하는 드라이버 복귀 주소를 제거한 것이 원인이었습니다.
  이제 모든 해제는 Filter Manager 호출 다음에 명령이 있는 인라인 금지 래퍼를
  거치므로 작업 항목의 소유권을 바꾸지 않으면서 드라이버 복귀 주소를 보존합니다.
- 이후 실행에서는 사용자 테스트 프로세스 종료 시 `0xCB`
  (`DRIVER_LEFT_LOCKED_PAGES_IN_PROCESS`) 버그 체크가 드러났습니다.
  `!lockedpages <process>`는 MDL 7개와 잠긴 페이지 정확히 11개를 확인했으며, 모두
  pre-WRITE와 pre-READ 교체 준비 지점의 `FltLockUserBuffer`에서 만들어졌습니다.
  이 호출들은 원래 사용자 버퍼용 MDL을 설치했지만, `apply()`가 같은 IOPB 필드를
  즉시 교체 MDL로 덮어써 중간 MDL이 원래 매개변수와 교체 MDL 양쪽 정리 경로에서
  모두 빠졌습니다. 이제 교체 준비 단계에서는 누락된 원본 MDL을 잠그지 않습니다.
  입력은 보호된 요청자 프로세스 연결 상태에서 복사하고, 출력은 하위 파일 시스템을
  호출하기 전에 건드리지 않습니다. 출력 되쓰기에서는 Filter Manager가 post 작업
  매개변수를 복원한 뒤에만 누락된 원본 MDL을 잠급니다. post 단계에서 만든 MDL은
  콜백 데이터에 남아 Filter Manager가 완료 시 잠금을 풀고 해제하게 합니다. 새로
  얻은 원본 MDL의 출력 범위가 반환 바이트 수보다 짧은 경우에도 되쓰기를 거부합니다.
- 통신 왕복은 처음에 `FltSendMessage`의 성공 심각도 `STATUS_TIMEOUT`을 정상 응답으로
  취급했고, 뒤늦은 사용자 모드 `FilterReplyMessage`의
  `ERROR_FLT_NO_WAITER_FOR_REPLY`를 치명적인 수신 오류로 처리했습니다. 이제 커널
  시간 초과는 `STATUS_IO_TIMEOUT`으로 정규화하며, 오래된 응답은 관련 없는 수신
  작업자를 종료하지 않고 폐기합니다.
- WDM Driver Verifier 실행은 기본 설정에서 검증 대상 풀 할당을 통해 리스트 노드
  8천만 개를 삽입하는 cppreference PMR 벤치마크 때문에 거의 46분이 걸렸습니다.
  이제 일반 드라이버 테스트는 크기가 제한된 의미 검증 작업량을 사용합니다. 원래
  규모의 스트레스 테스트는 명시적인 `CRTSYS_TEST_EXTENDED_PMR_BENCHMARK` CMake
  옵션을 통해서만 사용할 수 있습니다.
- 처음으로 WDM 기능 테스트 전체를 통과한 뒤 드라이버를 언로드하자, Driver
  Verifier가 총 32바이트인 비페이징 할당 두 건 때문에 `0xC4/0x62`로 중단했습니다.
  `_VI_POOL_ENTRY` 레코드를 추적한 결과 LDK의 `RtlEnterCriticalSection`이 할당하고
  UCRT 잠금 테이블 항목 4(`locale`)와 5(`multibyte code page`)가 참조하는 활성
  `LdCs` 특수 풀 블록 두 개였습니다. Release 빌드는 사용자 프로세스 종료 의미에
  따라 UCRT 정리 함수를 의도적으로 생략하는 `terminating=true`를
  `__scrt_uninitialize_crt`에 전달했습니다. 드라이버 언로드는 프로세스 종료가
  아니므로 이제 해체 시 항상 `false`를 전달해 잠금 소멸자를 실행합니다. 수정된
  x64 Release WDM 드라이버는 이후
  `0xC4/0x62` 중지 없이 Driver Verifier에서 로드와 언로드를 정상적으로
  완료했습니다. 전용 미니필터 테스트도 같은 수정 런타임으로 다시 빌드했으며,
  Driver Verifier에서 자체 언로드를 문제없이 완료했습니다.
- 독립 소비자/테스트 빌드가 서로 다른 구성의 비공개 `crtsys.lib`를 같은 소스 트리
  `lib/<arch>` 디렉터리에 기록했습니다. 그 결과 미니필터 빌드가 WDM 테스트
  라이브러리를 덮어써 이후 증분 링크에서 테스트 전용 심볼이 사라질 수 있었습니다.
  이제 최상위 빌드만 소스 트리 라이브러리 디렉터리에 게시하고, 종속성 빌드는 자체
  바이너리 트리에 라이브러리를 유지합니다.
- 공개 미니필터 API에서는 호출자가 원시 단계 인수를 지정해 형식화된 pre/post
  래퍼를 우회할 수 있었습니다. 이제 원시 구현과 단계 열거형은 내부 세부
  사항이며, 전체 작업 형식 컴파일 행렬로 매핑이 형식화된 pre/post 작업만
  허용함을 검증하고, 교체는 형식화된 pre 작업만 허용함을 검증합니다.
- 이전 WDM 검증은 IOCTL 전송 방식 네 가지를 모두 다뤘지만 자동 READ/WRITE 분류,
  경고 상태 완료 길이 제한, FSCTL minor function 게이트는 직접 실행하지 않았습니다.
  이제 커널 테스트가 이 계약들을 검증하며, 미니필터 앱은 의도적으로 EOF를 넘는
  범위를 읽어 `IoStatus.Information`이 지정한 접두사만 변환되어 되써지는지
  확인합니다.

  `call FltFreeGenericWorkItem`, 드라이버 `nop` 및 `ret`가 이어집니다.
- [x] 미니필터 언로드를 반복하고 필터 확인 프로그램이 둘 다 보고하지 않는지 확인합니다.
  오래된 일반 작업 항목 레코드나 실제 리소스 누출이 없습니다.
- [x] 잠긴 페이지 추적을 사용하여 전체 미니필터 프로세스 종료 경로를 반복합니다.
  `!lockedpages`에 교체 전 `FltLockUserBuffer` 호출에서 만들어진 MDL이 남지 않고
  `0xCB`가 발생하지 않는지 확인합니다.
- [x] 최종 x64 미니필터 Driver Verifier 실행은 전체 4KiB 암호화/복호화 왕복과,
  크기가 큰 짧은 읽기에서 센티넬 꼬리가 그대로 유지되는 사례를 포함한 매핑 읽기
  여섯 가지, 그리고
  시간 초과·연결 끊김·해체 취소 경로 여섯 가지를 모두 실행했습니다. Filter
  Verifier에서는 균형 잡힌 로드/언로드, 일반 작업 항목 경고 없음, 잠긴 페이지
  중지 없음, 리소스 누수 없음을 확인했습니다. UCRT 언로드 수정으로 다시 빌드한
  뒤에도 테스트가 통과했으며, 마지막 실행 후 Verifier 조회 결과
  `crtsys_flt_io_buffer_runtime_test.sys`는 로드 8회/언로드 8회, 태그 없는 풀이나
  추적되지 않은 할당 0건으로 보고되었습니다.
- [x] WDM 사용자 애플리케이션은 자동 IRP를 포함한 15가지 테스트를 모두 완료했습니다.
  여기에는 자동 IRP 입력/출력 의미와 되쓰기, 연결 해제 시 강제 매핑 해제,
  프로세스 종료 시 닫기가 포함됩니다. UCRT 종료 의미를 수정한 뒤에는 강화된
  커널 측 READ/WRITE/FSCTL 테스트도 `DriverEntry`에서 통과했고, `sc stop`과 서비스
  삭제도 정상 완료됐습니다. Verifier는 `crtsys_test.sys` 로드 2회/언로드 2회와
  태그 없는 할당 0건을 보고했습니다.
  추적되지 않은 할당.
- [x] 공개 미니필터 예제는 서로 독립적인 `basic`, `communication`, `swap-buffers`
  프로젝트로 나뉩니다. 마지막 예제는 대소문자를 구분하지 않는 `.ntlxor` 파일의
  pre-WRITE 교체 버퍼와 post-READ 교체 버퍼 중 `IoStatus.Information`으로 지정된
  유효 접두사만 XOR합니다. 대상 Fast I/O를 허용하지 않고, 할당과 되쓰기를
  PASSIVE_LEVEL 지연 처리로 수행하며, 일반 `.tmp` 스트림은 변경하지 않습니다.
  XOR과 파일 선택 정책이 제품용 암호화가 아닌 이유도 문서화합니다. x64 `/W4 /WX`
  드라이버/앱과 x86 교차 비트 앱 세 개가 모두 빌드되며, 별도의 x64 VM 스모크
  실행에서 기본 파일 수명, 통신 포트 기능, `.tmp`/`.ntlxor` 교체 경로, 언로드,
  서비스 삭제를 완료했습니다.
- [x] 세 가지 공개 샘플 INF는 모두 DIRID 13을 사용하며
  `Parameters\Instances`에는 고유한 서비스/인스턴스/고도 ID가 있습니다.
  WDK 10.0.28000 `InfVerif /w`를 전달합니다.
- [x] IRP 매핑 단계를 정책과 분리했습니다. 완료 전 호출자는
  `try_map_io_buffers`를, 완료 후 호출자는 `try_map_completed_io_buffers`를
  사용하며, `map_io_options`에는 더 이상 완료 상태 불리언이 없습니다.
- [x] 미니필터 스왑 선택을 작업 유형으로 만들었습니다. 읽기/쓰기 및 기타
  단일 방향 작업은 유일한 유효한 방향을 추론합니다. QUERY_EA,
  QUERY_QUOTA, FSCTL, IOCTL 및 내부 IOCTL에는 `swap_buffer`가 필요합니다.
  컴파일 시간 테스트에서는 역 과부하, 선택기로서의 정책 호출,
  지원되지 않는 작업 및 방향 부울 반환
  `swap_io_options`.
- [x] x64/x86용 WDM 및 미니필터 런타임 드라이버, x64 Debug/Release의 미니필터
  Visual Studio 예제 3개를 모두 다시 빌드하고 Visual Studio 예제 프로젝트 22개를
  검증했습니다. WDM VM 픽스처는 완료 후 매핑 진입점을 사용한 테스트 15개를 모두
  통과했고, swap-buffers VM 샘플은 `.tmp` 통과 경로, `.ntlxor`의 쓰기 전/읽기 후
  왕복, 언로드 및 서비스 삭제를 통과했습니다.
